# Android development: build and install

[Developer guide](DEVELOPER.md) · [iOS development](IOS_DEVELOPMENT.md)

These instructions use macOS and run commands from the repository root unless
stated otherwise. The Android host is experimental and is not in the release
workflow. Its app name is **Fluux Messenger Android Dev**, with application ID
`com.processone.fluux.android.dev`.

## Install the toolchain

Install Node.js 24 and Rust, then install [Android Studio](https://developer.android.com/studio)
for your Mac architecture. Launch it and complete its setup wizard. Open
**SDK Manager** from the welcome screen or Android Studio settings.

In **SDK Platforms**, install Android SDK Platform 36, used by the current
Tauri-generated Gradle project. A newer platform does not replace platform 36. In **SDK Tools**,
install Android SDK Platform-Tools, Android SDK Build-Tools, Android SDK
Command-line Tools (latest), and NDK (Side by side). Apply the changes and accept
the required licenses. Use JDK 21 for the Gradle wrapper generated by Tauri.
Recent Android Studio versions may bundle Java 25, which cannot run this
Gradle 8.14.3 wrapper. If JDK 21 is missing, install a macOS JDK 21 distribution
such as Eclipse Temurin before continuing.
See the [Gradle Java compatibility matrix](https://docs.gradle.org/current/userguide/compatibility.html).
See the [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/#android).

Add these exports to `~/.zshrc`, using the SDK location shown in SDK Manager if
it differs from the default:

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export NDK_HOME="$ANDROID_HOME/ndk/REPLACE_WITH_INSTALLED_VERSION"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
```

Get the exact NDK directory name with `ls "$HOME/Library/Android/sdk/ndk"` and
replace `REPLACE_WITH_INSTALLED_VERSION`. Select one installed version explicitly
when multiple versions exist. Reload the shell configuration and verify it:

```bash
source ~/.zshrc
java -version
adb version
sdkmanager --version
ls "$NDK_HOME/toolchains/llvm/prebuilt"
rustup target add aarch64-linux-android
npm ci
npm run tauri:android:init
```

Run initialization once per checkout, and again after native plugin or Android
configuration changes. It generates `apps/fluux/src-tauri/gen/android/` and runs
the manifest/network preparation hook. Generated projects are ignored by Git;
do not copy them between worktrees or hand-edit them.

## Prepare a phone or emulator

On a physical Android phone, enable Developer options and **USB debugging**,
connect it by USB, unlock it and accept the computer authorization prompt.
Run `adb devices -l`: the selected device must show `device`, not `unauthorized`
or `offline`. The current host requires Android API 24 or newer.

For an emulator, install **Android Emulator** in SDK Manager and create an AVD
in Android Studio's **Device Manager**. Use an ARM64 system image on Apple
silicon and start the AVD before launching Fluux. An x86_64 emulator additionally
requires `rustup target add x86_64-linux-android` and a build targeting `x86_64`.

## Run with hot reload

```bash
npm run tauri:android:dev
```

Select the device or emulator when prompted. Keep the command running while
editing. It builds the SDK, prepares the Android project, starts Vite and runs
the development app. To work through Android Studio instead:

```bash
npm run tauri:android:dev -- --open
```

The dev app needs the development server. Check the address printed by Tauri if
the app cannot load; USB debugging authorization alone does not prove that the
WebView can reach that address. See [Tauri mobile development](https://v2.tauri.app/develop/#developing-your-mobile-application).

## Build and install a standalone debug APK

For an ARM64 phone or emulator:

```bash
npm run tauri:android:build -- --debug --target aarch64
rg --files --hidden --no-ignore apps/fluux/src-tauri/gen/android/app/build/outputs/apk -g '*.apk'
adb devices -l
```

Use the APK path printed by the build (or the listing), and the serial printed
by `adb devices`. Replace both placeholders below:

```bash
adb -s DEVICE_SERIAL install -r "PATH_TO_DEBUG_APK"
```

Launch **Fluux Messenger Android Dev** from the device's launcher. This APK embeds
the frontend and runs without Vite. An XMPP server is still needed to sign in.
`install -r` updates the app while preserving its data when the application ID
and signing certificate match. A signature mismatch requires the original
signing key or a deliberate uninstall; uninstalling deletes the app's local data.
See [Android Debug Bridge](https://developer.android.com/tools/adb#move).

Keep `--debug` for this workflow: removing it selects a release build whose
signing/distribution setup is separate. No Play Store upload is involved.

## Proxy, generated configuration and limitations

The proxy supports STARTTLS, direct TLS and SRV discovery using Android's active
network DNS servers. Its Java application context is initialized before proxy
startup. Android TLS uses bundled Mozilla public roots (`webpki-roots`) with
certificate and XMPP-domain verification; private CAs installed on the phone
are not supported by this version. Root updates require rebuilding the app.
iOS retains Apple's verifier and desktop retains its system certificate loader.

Cleartext WebSocket access is allowed only to loopback for the in-process
proxy; upstream XMPP still negotiates TLS. The WebView uses the HTTP asset scheme
so this loopback WebSocket is not blocked as mixed content. The generated main
network policy denies other cleartext traffic; Tauri's debug development policy
may additionally permit access to the development server.

Check preparation with `npm run test:android`, and native changes with
`cargo test --locked` and `cargo clippy --locked -- -D warnings` from
`apps/fluux/src-tauri`. A desktop test run does not validate the Android JNI
bridge, APK installation or a live connection on a phone. Background connection
survival and push notifications are not implemented by this host.


If using the raw Tauri CLI after initialization, run
`npm run tauri:android:prepare -w @xmpp/fluux` first. The repository's npm
`init`, `dev` and `build` commands already run this preparation automatically.

## Troubleshooting and validation

- **Unsupported class file major version 69:** select JDK 21 with
  `export JAVA_HOME="$(/usr/libexec/java_home -v 21)"`. In Android Studio, select
  the same JDK in the Gradle settings when building through the IDE.
- **SDK not found:** check `ANDROID_HOME` against SDK Manager's location and run
  from a terminal that has loaded the exports.
- **Android Clang not found:** check `NDK_HOME` and that NDK (Side by side) is
  installed; SDK Platform-Tools alone do not supply the native compiler.
- **Licenses not accepted:** complete SDK Manager's prompts or run
  `sdkmanager --licenses` interactively.
- **No device / unauthorized:** unlock the phone, enable USB debugging and
  accept its authorization prompt; confirm again with `adb devices -l`.
- **Wrong CPU / no matching ABI:** match `--target` and the Rust target to the
  device or emulator architecture.
- **TLS rejected:** use a valid public certificate for the XMPP domain. This
  Android proxy version does not use private CAs installed on the phone.

After installation, check launch, login, message send/receive, disconnection and
reconnection. Test both a `wss://` endpoint and a native proxy connection, such
as `tls://xmpp.example.org:5223`, with your own server. Verify certificate failure
handling as well as successful connections. Background delivery is not promised.

The ARM64 debug APK was built on macOS with JDK 21.0.11, NDK 30.0.16248370,
SDK Platform 36 and Build-Tools 36.0.0 on 2026-09-25. APK signature verification
passed; the package declares `com.processone.fluux.android.dev`, minimum API 24
and the `arm64-v8a` ABI. The generated file is
`apps/fluux/src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`.
Despite the `universal` filename, this build contains only the requested ARM64 ABI.

This verifies cross-compilation and packaging, including compilation of the
Android JNI bridge. Installation, JNI execution and a live phone connection
remain unverified. Record those device results separately when running this guide.

## Receive shared content

Re-run `npm run tauri:android:init` after changes to the sharing plugin.
The preparation script registers a dedicated `ACTION_SEND` activity and
prepares localized native messages. It copies a granted `content://` file into
the app's private inbox before opening Fluux, so the original app's temporary
permission can expire safely. Links are stored as text. No storage permission
or network transfer is required to import.

Choose **Share → Fluux** in another app, then select a contact or joined room
and press Send after reviewing the preview. Closing the picker retains the
original; Delete removes it. Failed sends and restarts preserve pending imports.
The picker does not replace conversation drafts. Text edits in the picker are
session-local. Imports are device-local and can be sent with the account chosen
at login; no recipient is assigned by the source application.

The first version accepts one link or one file, up to 20 MiB, with 20 pending
items. It does not register `ACTION_SEND_MULTIPLE`. The server's upload limit
also applies. Test cold and warm starts, an image and a document from real
content providers, logged-out import, cancellation, upload failure and restart
before sending on an emulator or device. A compiled APK alone does not establish
that these provider and lifecycle cases work.
