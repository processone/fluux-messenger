# Local sccache evaluation — 2026-09-14

## Decision

Do not adopt sccache in the local development workflow. The observed saving when
building in another worktree was too small to justify the additional installation
and configuration, and small source edits showed no clear improvement. This
evaluation is complete; it introduces no compiler wrapper or linker override.
Keep Cargo's normal local caching and incremental compilation, and retain
`Swatinem/rust-cache` in CI. These measurements do not compare CI cache strategies.

## Method

- Revision: `9e3f5c89c0d2bdbb5f9bae92884e82157f25bff1`.
- Host: macOS 26.5.2 ARM64, ten logical CPUs; Rust 1.95.0, sccache 0.17.0.
- Three detached worktrees, A, B and C, with independent `target` directories.
- Command from `apps/fluux/src-tauri`: `cargo build --locked --offline --timings -j 2`.
- Existing Cargo registry shared across runs. An empty `target` is not an empty
  registry or a cold operating-system filesystem cache.
- Repository development profiles and default incremental compilation retained;
  default linker; development TLS with ring.
- Isolated local sccache directory with a 10 GiB limit, no remote backend, and
  `SCCACHE_BASEDIRS` containing the worktree roots. Only cached runs set
  `RUSTC_WRAPPER` to the sccache executable.
- B filled the cache. A was rebuilt with an empty `target`, followed by a fresh C.
  A second uncached build followed C, reversing the initial comparison order.
- Short rebuilds changed one startup diagnostic string in `src/main.rs`. Three
  further edits per mode alternated A without sccache and C with sccache. Original
  source bytes were restored after each edit.
- Native development builds only: frontend compilation, bundling, application
  startup, tests, Clippy and production builds were excluded.

## Results

| Scenario | Without sccache | With sccache |
| --- | ---: | ---: |
| Empty target, cache already filled in another worktree | 138.6 s; 157.6 s | 121.0 s; 127.5 s |
| First build filling an empty sccache | — | 149.6 s |
| Small Rust edit, median of three alternating measurements | 4.47 s | 4.36 s |

The two empty-target comparisons average 148.1 s without sccache and 124.3 s with
it: an observed saving of 23.8 s, or 16.1%. This is an order of magnitude, not a
precise performance guarantee. System load varied from 4.5 to 14.8 on one-minute
averages, and swap was already in use before the first build. Two full passages
per case cannot establish statistical significance. The first cache fill took
about as long as an uncached build.

Both recipient worktrees reported 382 Rust cache hits and 180 Rust cache misses:
68% of eligible Rust lookups hit the cache. All 26 eligible C/C++/assembler
compilations were reused. A hit count is not a fraction of build time saved:
several expensive dependencies, including objc2-app-kit, Tauri and Sequoia, still
compiled. Procedural macros, build-script binaries and the final application
also account for calls that are not eligible for caching.

Cargo timing reports and per-run sccache counter differences supplied these
observations. CPU totals from timing the Cargo process were not compared because
compiler work behind the separate sccache server would not be accounted for in
the same way.
